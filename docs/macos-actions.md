# macOS builds on GitHub Actions

Pull requests build Windows x64, macOS Apple Silicon (`macos-15`), and macOS Intel (`macos-15-intel`). Mac artifacts contain a DMG and a compressed app bundle that preserves executable permissions and symlinks. The PR apps are ad-hoc signed, not Developer ID signed or notarized. They are test artifacts, not trusted distribution releases. No signing secrets are exposed to PR jobs.

## Enable signed Mac releases

The existing local `build_release_mac.sh` remains available. It currently builds Apple Silicon only and uses credentials from the local Mac. Those credentials do not automatically exist on GitHub runners.

The repository owner must securely configure these repository Actions secrets directly in GitHub settings. Do not paste private keys, certificates or passwords into chat, issues, PRs or source files:

- `APPLE_CERTIFICATE`: Base64-encoded Developer ID Application certificate and its private key, exported as a password-protected `.p12`
- `APPLE_CERTIFICATE_PASSWORD`: Password protecting that export
- `APPLE_SIGNING_IDENTITY`: Exact `Developer ID Application: …` identity
- `APPLE_API_ISSUER`: App Store Connect team API issuer ID
- `APPLE_API_KEY`: Existing App Store Connect API key ID
- `APPLE_API_KEY_CONTENT`: Contents of the matching private `.p8` key used for notarization
- `TAURI_SIGNING_PRIVATE_KEY`: Existing Tauri updater key, matching the app's public key; this is independent of Apple's signing identity. This repository's workflow uses an empty updater-key password

After configuring and authorizing these credentials for CI, set repository Actions variable `MACOS_RELEASE_ENABLED` to `true`. This opt-in grants the release workflow use of the configured Apple credentials. No credentials are generated by the workflow. Tauri imports the configured certificate into the ephemeral runner's keychain; the notarization key file is private and removed after the build step.

Before opt-in, Windows releases continue normally and Mac release jobs are skipped. After opt-in, missing credentials fail closed; the workflow never substitutes unsigned Mac release assets. A Developer ID identity and valid notarization tickets are checked before upload. Apple Developer membership and valid credentials are required, but are not verified by a PR build.

## Release behavior

Publish a **new, version-matched release** whose tag points to a commit already on `main`. Publishing triggers all enabled platform builds. The updater manifest is combined once after all enabled builds succeed, preserving `windows-x86_64` and adding `darwin-aarch64` and `darwin-x86_64`. Mac updates use signed `.app.tar.gz` archives; DMGs are separate downloads. The release publisher validates all existing assets before uploading anything and never replaces different existing bytes. A replay with identical assets is harmless; a rebuilt binary can differ, in which case the job intentionally fails rather than overwrites.

Do not retag or rerun an old release to add these changes. In particular, this PR does not alter v0.3.4 or its existing `latest.json`. If the local Mac release script is used, do not run it concurrently with Actions: the legacy script replaces `latest.json` itself.
